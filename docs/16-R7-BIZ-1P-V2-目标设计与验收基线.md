# R7-BIZ-1P V2 目标设计与验收基线

本文件与七份正式设计和测试文档中的“V2 目标基线修订”共同落实《R7-BIZ-1 V2 评审决策冻结记录》。本文件描述未来 BIZ-1A～1D 的目标，不代表当前 API、数据库或双端已经实现。当前可调用契约仍以 `docs/openapi.yaml` 和现行代码为准；各阶段实现时同步 OpenAPI。原 V1.0 文档中凡与 V2 冻结记录或本文件对应章节冲突的说法均已废弃，原文仅保留历史追溯。出现冻结记录内部冲突必须停止实施并标记 DECISION REQUIRED。

## 01 需求规格 V2 目标基线

- Driver.driverType 是 INTERNAL/OUTSOURCED 的唯一业务来源，不能从 Role、绑定、工资或线路反推。DRIVER Role 只表示系统账号身份。系统管理不得创建或分配 DRIVER；司机业务流程创建或关联 User，并管控司机类型变更时的绑定、未完线路、工资和历史。
- INTERNAL 使用公司 vehicle 和司机车辆绑定，发布、发车按既有公司车辆规则校验。OUTSOURCED 不绑定公司车辆，不创建 vehicle/FK，不要求 vehicleId；外协车牌仅是每条线路参与事实，不校验公司车辆存在、归属、保险、绑定或状态。
- Route 有 N 条有序 Participant。每条记录保存司机及类型事实、INTERNAL 公司车或 OUTSOURCED 车牌、INITIAL/TRANSFER、指派/发车/结束时间、结束方式、转派原因和当前核定工资；任何一次转派不得覆盖前一参与事实。
- 初始司机即第一参与，初始工资即第一参与工资；外协初始发布必须有真实外协车牌及工资。普通未执行初始指派取消后，其工资和车辆费用资格不计入有效口径，历史仍保留。首次转派后，未发车再次换人也只能继续转派。转派封存上一参与、创建新当前参与，新司机重新发车；转派过程中不得作废，最终必须由当前司机卸货。
- 转派权限可在该动作中重核所有既有参与工资、填新司机工资、以原因留痕；工资可为 0.00，只有金额变化才记调整历史。非转派工资修改需要独立权限和原因。线路有效工资是所有纳入有效参与口径的当前核定工资之和。
- 所有正式 INTERNAL 参与公司车辆均具备该线路费用资格，和是否已点击发车、工资是否为零无关；外协车牌无公司线路费用资格。能源费用使用整条线路首次发车至最终卸货窗口，0/多匹配不猜，唯一匹配才自动归属。所有正式费用在授权下可重新归属，前后线路、操作人、时间、原因永久保留。
- 公司费用事实与线路归属分离。未归属有效费用不计单线路支出，但必须计入公司总支出；重新归属只改变线路间分布，不改变公司总费用。线路费用与日常费用仍按各自业务归属，日常费用不分摊线路。
- 只有当前有效参与司机可最终卸货，且必须有当前参与司机/车辆及至少一张合法磅单。磅单进入正式 Attachment 并绑定原始卸货/重量事实；后续重量纠错不覆盖原图。毛重必须大于皮重，净重系统计算，不达标仍允许卸货。
- INTERNAL 达标为 TRUE/FALSE，OUTSOURCED 为 NULL/不适用；达标率分母仅含适用线路。司机线路列表/详情 API 不返回单价、任何参与工资、收入、利润、达标或阈值；本人正式工资单由 salary:mine 提供。
- 只有 COMPLETED 线路可作废，原因必填，UI 明确告知经营影响并要求勾选确认。作废后该线路收入、工资、归属线路费用和利润不再计入当前有效线路经营；全部事实和公司真实发生费用仍保留，公司总费用不因作废消失。VOIDED 恢复固定回 COMPLETED。
- 线路导入区分新线路导入与上线前已完成历史线路导入。历史导入带 HISTORICAL_IMPORT 来源、ImportTask/Row 追溯，进入 COMPLETED 历史经营与月结；不得再发布、发车、转派、卸货。历史模板待真实文件提供，不臆造字段。
- 已完成线路列表显示净重、达标/不适用、收入、总支出、利润；详情展示参与、转派、重量、原始磅单、工资与调整历史、正式费用及来源、支出构成和状态操作历史。金额按经营/财务权限控制。
- 月结旧快照永久不变，新版本说明工资、重量、费用新增/冲销与归属、线路作废/恢复的前后事实和金额影响；审批费用摘要只需发起日期、类型、金额、发起人、最终通过人、通过时间。
- “打回指定节点”正式改称“打回指定步骤”：目标是冻结流程的稳定 Step/Node ID；只有当前实例实际合法前置步骤可返回时显示；同岗位/审批人重复需显示第 N 步，禁止用户手填序号，动作历史不可覆盖。
- audit_log 目前只有查询能力。BIZ-1A 必须建立写入底座，后续记录转派、工资、作废/恢复、费用归属、重量和角色权限等高风险变化，专项历史表继续保留。

## 02 功能与 ER V2 目标基线

目标关系：User 0..1 → Driver；Driver 1 → N RouteParticipant；RouteTask 1 → N RouteParticipant；RouteParticipant 1 → N ParticipantSalaryHistory；RouteTask 1 → N RouteWeightVersion；原始卸货重量版本 1 → N FileAttachment；RouteTask 1 → N ExpenseEntry（仅有效线路归属），ExpenseEntry 1 → N ExpenseAttributionHistory；SettlementVersion 1 → N SettlementDetail/Diff；高风险对象 1 → N audit_log。多态附件与审计不强制数据库外键，但服务层必须校验归属和访问。

RouteTask 是线路主体与最终经营结果，Participant 是司机/车辆参与权威历史。顺序唯一、同一线路最多一个当前参与；INITIAL 后可接任意个 TRANSFER。INTERNAL 参与指向公司 vehicle 并保留发车快照；OUTSOURCED 参与仅存车牌快照，不以车牌创建设备资产。普通取消记录结束事实，不抹除。工资既有单线路字段在过渡期仅可作为兼容派生值，最终以参与工资之和为准。

线路主状态目标：UNPUBLISHED → PUBLISHED（待首位司机发车）→ IN_TRANSIT → COMPLETED；发生转派时进入“等待接手司机发车”的明确业务状态，再由当前参与司机发车回 IN_TRANSIT。最终枚举名由 BIZ-1A 确定。未进入转派链且未执行的指派可普通取消并重新指派；转派链在最终卸货前不可作废或普通取消。只有 COMPLETED → VOIDED，VOIDED → COMPLETED，包括已经完成的转派线路。历史导入直接成为只读执行历史的 COMPLETED，允许按完成线规则作废。

参与状态目标：INITIAL/TRANSFER 为来源，不是完成状态；当前待发车 → 已发车 → 因转派结束或因最终卸货完成。未执行 INITIAL 可以普通取消并保留历史；已进入转派链的待发车参与只能被下一次正式转派结束。当前参与是唯一发车/卸货授权对象。状态与工资/费用资格分别建模：正式 TRANSFER 参与即使未发车，其核定工资和 INTERNAL 车辆资格仍有效。

## 03 MySQL 物理设计 V2 目标基线

仅设计下一 Flyway V8，不修改/执行 V1～V7 或 database.sql。建议新 route_participant 以 bigint 主键、route_id、sequence_no、driver_id、driver_type_snapshot、company_vehicle_id 或 outsourced_plate_no、source_type、status、assigned_at、departed_at、ended_at、end_reason、transfer_reason、salary_amount、version、operator 时间等组成。以 (route_id, sequence_no) 唯一；用受锁的 route_task 当前参与引用或等效数据库唯一约束确保同一路线只有一个当前参与。按 (driver_id, status)、(company_vehicle_id, route_id) 建业务索引。

参与工资历史以 participant_id、before_amount、after_amount、reason、operator_id、operation_time 关联；金额 DECIMAL，允许 0，禁止负数。原始磅单通过 file_attachment 的新 purpose 与重量版本/卸货事实关联，可用关联表表达 1:N；调整证据保持独立目的和引用，附件读取按路线参与/授权角色校验。外协车牌不设 vehicle FK；多态附件/审计保持服务层一致性边界。expense_entry 与 expense_attribution_history 继续为费用及归属权威，增加必要的参与车辆资格查询索引，不复制费用金额为第二事实。SettlementDetail/Diff 保留不可变快照、业务对象来源和操作来源；audit_log 复用既有表并增加写入服务。

既有库升级前只读盘点外协脏绑定、类型变化、无车牌参与、未完线路和单线路工资；能由可靠指派/发车事实确认的首参与可回填，不能推断的历史标记资料不完整，绝不凭公司车绑定猜外协牌照。旧月结不改。继续执行的新业务记录必须在动作前补齐真实必填信息。空库从 V1 顺序执行至 V8 并校验约束；实际字段、索引及兼容旧列在 BIZ-1A 按 Repository 依赖定稿。

## 04 API 目标契约 仅 proposed 尚未实现

- BIZ-1A：司机业务入口创建/关联 DRIVER User、driverType 变更校验、外协绑定拒绝；线路参与基础只读契约及新状态字段。
- BIZ-1B：参与历史查询；按当前参与版本转派，提交新司机/外协车牌、所有工资核定及原因；独立参与工资调整、参与工资历史查询。转派与工资调整使用权限和幂等请求标识。
- BIZ-1C：按线路查询合格 INTERNAL 公司车辆候选；费用列表增加具体 routeId 筛选；正式费用重新归属；完成线路分页经营摘要及详情经营组成；公司利润单列未归属有效费用；月结看板/分组明细/差异来源采用批量或分页契约，避免 N+1。
- BIZ-1D：卸货请求增加非空磅单 attachmentIds；附件增加卸货专用 purpose/上传/只读查询与路线参与授权；达标三态；司机专用线路 DTO 删除财务与达标敏感字段。毛重/皮重仍同页提交。
- UI-FIX：审批实例合法可打回步骤的只读列表和使用稳定 Step/Node ID 的打回动作；审批详情业务摘要、月结及线路经营 UI 依赖以上已实现契约。具体端点命名以实施阶段 OpenAPI 更新为准，不在本阶段声称已上线。

当前正式 docs/openapi.yaml 必须与已实现 API 保持一致，因此本阶段不写入 proposed 端点。BIZ-1A～1D 分阶段同步 OpenAPI；既有路径保留兼容策略后再废弃。费用 Excel/CSV 模板未提供，不制定来源、列映射或唯一键。

## 05 页面交互与状态 V2 目标基线

管理端线路区分“当前线路”和“线路历史”；列表按状态、权限显示直接可执行动作，完成历史显示经营总计，详情按概况、参与/转派、重量磅单、工资费用、状态与审计组织。转派为独立任务表单，确认新司机/外协车牌、既有及新参与工资、原因，并显示操作影响。完成线作废弹窗逐项说明收入、工资、归属费用与利润退出当前有效线路经营，并要求明确勾选确认；未完成及转派中不出现作废。

司机小程序只显示本人当前或历史参与线路，当前参与决定发车/卸货权限。卸货流程为重量→至少一张磅单→摘要确认→提交；弱网结果未知时查询状态，不重复提交。无论司机类型均不展示达标或财务字段；外协车牌不表现成公司车辆绑定。当前司机可见当前任务，历史司机仅看其参与历史，不可卸货。

费用界面选择线路后只列符合资格的公司车辆；支持正式费用重新归属及按具体线路筛选，使用可搜索业务选择器而非手填 ID。公司看板区分线路费用、日常费用和有效未归属费用。月结采用经营看板→版本明细→与前版差异，JSON 仅高级查看。审批详情为结构化业务单据和动作表；“打回指定步骤”展示第 N 步、步骤名和审批人辅助信息，只列实际可返回步骤，不让用户手填序号。系统用户表单不允许选择 DRIVER，权限以中文业务语义呈现，仍保留精确权限码作高级信息。

## 06 权限与强校验 V2 目标基线

- route:transfer（新）：可转派并在同一动作中重核该线路所有正式参与工资，不另需独立工资调整权限；原因必填，当前参与与版本必须匹配。
- route:salary:adjust（新）：非转派场景调整任意参与工资，含 0.00；原因必填，金额变化才生成历史；普通 route:edit 不能代替。
- route:void、route:reactivate（沿用）：仅 COMPLETED 可作废，VOIDED 恢复 COMPLETED；作废原因必填。权限赋予角色，不硬编码 ADMIN。
- route:list、route:depart、route:unload（沿用）：司机仅本人参与范围，且只有当前有效参与可发车/卸货。route:list 本身不授予经营金额；敏感金额需独立经营/财务权限，由实施阶段核定最小可复用权限或增码。
- salary:view、salary:mine（沿用）：前者授权管理端查看，后者仅自有司机本人正式工资单；外协仍强拒绝工资单。费用申请/处理保持既有业务红线，外协不因新增参与而获公司费用能力。
- driver:add/edit、user:manage、driver:bindVehicle（沿用并加 Policy）：DRIVER 账号只能由司机流程创建/关联；外协绑定后端强拒绝；类型变更校验当前绑定、在途线路及历史。
- expense:attribution:edit、report:profit、settlement:view/diff:view、audit:view（沿用）：重新归属、经营金额、版本差异和审计须各自鉴权。附件下载再次校验用户及业务对象归属；前端按钮隐藏不代替后端拒绝。

## 07 测试与验收 V2 目标基线

以下为 BIZ-1A～1R 必须新增的未来用例，不表示本阶段已经执行：

- A01 用户管理不能创建/分配 DRIVER，司机流程原子创建/关联 User；driverType 变更受绑定、未完线路、工资历史保护。A02 OUTSOURCED 绑定 API、候选均拒绝；外协线路无 company vehicle 仍可按真实车牌与工资发布。
- B01 三次以上转派顺序、快照和历史完整；B02 转派后未发车再次转派只能继续转派；B03 转派与卸货并发仅一个成功，旧司机卸货 403/业务拒绝；B04 转派链最终卸货前作废拒绝，完成后按完成线规则可作废。
- B05 转派工资重核所有参与，新工资必填，可为 0.00；相同金额不追加历史。B06 独立工资调整需要独立权限与原因；路线工资合计正确，普通取消初始指派不计。
- C01 多 INTERNAL 参与公司车都可产生该线路费用，OUTSOURCED 车牌不可；查询时资格和正式落账时资格一致。C02 能源费用按全线时间窗口 0/1/多匹配处理。C03 正式费用在归属/未归属间双向调整留历史，线路利润随之变化，公司总费用保持。C04 未归属有效费用进入公司总支出，公司利润不虚高且不重复扣减。
- D01 仅当前有效参与司机可完成卸货；无磅单、错误 purpose、跨线路/他人附件均拒绝；上传成功卸货失败不产生假证据；纠错原图不覆盖。D02 INTERNAL 达标真/假、OUTSOURCED 不适用，达标率仅适用分母；未达标仍可卸货。D03 司机 API 不含单价、任何工资、收入、利润、达标及阈值，salary:mine 仍按本人与类型授权。
- R01 新线路导入走正常状态机；历史线路导入直接 COMPLETED，不能再次发布/发车/转派/卸货，ImportTask/Row 与来源可追溯。R02 完成线列表及档案收入=有效重量×含税单价，支出=线路费用净额+所有有效参与工资；作废后线路经营退出，公司真实费用仍计。R03 只有 COMPLETED 可作废，原因与 UI 风险确认；恢复回 COMPLETED，历史与旧月结不变，新差异语义正确。
- R04 月结 V1 后工资、重量、费用、归属和作废/恢复形成可解释 V2 差异，操作人/时间/原因可靠；审批费用业务摘要够用。R05 审批同岗位多步骤可按稳定 ID 返回指定合法前置步骤，非法目标拒绝，历史不覆盖。R06 audit_log 有真实转派、工资、费用归属、作废/恢复、重量及角色权限高风险动作的前后值。R07 并发重复请求、迁移回填、既有库和 V1～V8 空库均验收。

## 08 旧规则替换清单

以下原 V1.0 断言在七份文档中仅作为历史描述保留，实施 V2 时不再作为目标规则：发车后绝对不能更换司机/车辆；运输中只能作废；运输中可作废；作废恢复统一到 PUBLISHED；司机无公司车一律不能发布；线路只有一个司机或一笔工资；外协可以绑定公司车辆；未归属有效费用完全不进入公司利润；历史线路导入后可重新执行；打回目标用用户输入节点序号；卸货只需毛重皮重；司机端显示达标或阈值。已执行的 V1～V7、database.sql 与当前 OpenAPI 仍忠实记录现行实现，不能因为目标文档提前篡改。

费用真实文件模板仍待用户提供；不得臆造充电桩、ETC、油卡或维修导入列和去重键。若新模板与上述规则产生新冲突，应另写明确变更记录后实施。
