# R7-BIZ-1P V2 设计与测试基线同步报告

本次仅更新需求、设计、权限和验收资料。V2 是后续实施目标，当前 Java、管理端、小程序、V1～V7、database.sql 与 docs/openapi.yaml 均未因本阶段改变。依据为 `docs/15-R7-BIZ-1-V2-评审决策冻结记录.md`；目标细节汇总于 `docs/16-R7-BIZ-1P-V2-目标设计与验收基线.md`。七份原 V1.0 Word 文档保留原正文供现行实现与历史追溯，文首加入 V2 目标基线修订，并显式声明冲突旧断言已废弃。

1. **AGENTS.md 变更纪律**：需求规格优先，状态机、利润、费用归属、审批、唯一性及核心关系属于需求变更，须先更新设计和测试基线再改代码；后端强校验、事务、幂等、历史不可破坏。已在 AGENTS.md 增加 V2 决策优先说明，改正与冻结记录冲突的核心业务概述；原 V1 文档的非冲突部分仍按既有顺序适用。
2. **修改文档**：AGENTS.md；七份 `docs/01`～`docs/07` Word；新增 `docs/15` 冻结决策仓库副本、`docs/16` 详细目标设计、本文。没有修改其它正式文档。
3. **未修改代码证明**：阶段开始与收尾均检查 `git status`。Java、Vue、小程序源码、Flyway、database.sql、OpenAPI 未出现本阶段改动。既有 `backend/src/main/resources/application.yml` 与 `mini-program/project.config.json` 本机差异原样保留；未读取或记录其中 Secret。
4. **旧规则冲突清单**：发车后司机/车辆绝不可更换、运输中只能/可以作废、恢复一律回 PUBLISHED、司机无公司车一律不能发布、单线路单工资、外协可绑定公司车、未归属有效费用不进公司总利润、历史线路可再次执行、打回手填节点序号、卸货无需磅单、司机端达标字段可见，均已由 Word 文首 V2 修订及 docs/16 第 08 章标记废弃。`docs/13`、`docs/14` 是早期 UI 现状审计，其中旧页面描述仍代表当时观察，不是新的业务目标权威。
5. **Driver/User**：driverType 唯一确定 INTERNAL/OUTSOURCED；DRIVER Role 与类型分离；User 管理不得人工分配 DRIVER；司机流程创建/关联账号，变更类型需审查绑定、未完线路与历史工资。
6. **车辆**：INTERNAL 继续公司车及绑定强校验；OUTSOURCED 无公司车 FK、绑定或保险/状态校验，外协车牌只存参与事实，不能由旧绑定猜测。
7. **Route Participant ER**：RouteTask 1:N 有序 Participant，INITIAL/TRANSFER 来源、司机类型快照、车辆 ID 或外协车牌、指派/发车/结束事实、原因和工资；至少约束顺序唯一、最多一个当前参与，历史不可覆盖。
8. **Route 状态机**：未发布→待发车→运输中→完成；转派后有明确等待接手阶段，接手司机再发车。仅未转派且未执行的初始指派可普通取消；转派链最终卸货前不能作废。只有 COMPLETED 可作废，VOIDED 恢复 COMPLETED；最终枚举名 BIZ-1A 定稿。
9. **Participant 状态机**：当前待发车→已发车→转派结束或完成；未执行 INITIAL 可普通取消，已转派链的待发车参与再次换人仍走转派；当前参与决定发车及卸货授权。
10. **工资**：初始参与工资就是初始线路工资。转派可重核所有正式参与及必填新司机工资，金额可 0；独立工资调整另需权限；仅金额变化追加历史，线路工资按有效参与合计。
11. **费用资格/归属**：所有正式 INTERNAL 参与车辆有线路费用资格，不取决于发车或工资；外协无资格。能源按整条线路发车至卸货窗口匹配，只有唯一匹配自动归属；正式费用授权重新归属，保留原/新线路及原因。
12. **公司/线路双口径**：未归属有效费用不进单线路利润，仍进公司总费用；重新归属不改变公司费用总额。作废移除当前有效线路经营贡献，不能抹去真实发生的公司费用。
13. **磅单**：最终当前参与司机卸货，至少一张正式附件绑定原始卸货/重量版本；后续重量纠错另存证据，访问需后端校验。
14. **达标**：INTERNAL 真/假，OUTSOURCED 不适用；达标率只统计适用分母，不达标不阻断卸货；所有司机线路 API 无达标及阈值。
15. **线路导入**：新线路导入进入正常状态机；已完成历史线路导入保留 HISTORICAL_IMPORT 与 ImportTask/Row，直接成为完成历史，不可再次执行。
16. **作废/恢复**：只有已完成可作废，原因与 UI 明确风险确认必需；只退出当前有效线路经营，不删除运输、附件、工资、费用或审批事实；恢复回完成。
17. **完成线路档案**：列表展示收入/支出/利润等总计，详情展示参与、车辆、重量磅单、工资、费用来源与历史；敏感金额仍需经营/财务权限。
18. **月结**：旧 Snapshot 永不改，新版本解释工资、重量、费用及归属、作废/恢复；目标页面为看板→明细→差异，JSON 仅高级信息。审批费用摘要限定发起与最终通过事实。
19. **审批打回步骤**：选冻结流程中当前实例合法的稳定 Step/Node ID；同岗位重复显示第 N 步；不允许裸序号输入，Action 历史不覆盖。
20. **Audit**：正式记录 audit_log 当前可查但无统一写入。BIZ-1A 建写入底座，后续覆盖转派、工资、作废/恢复、费用归属、重量及角色权限高风险动作；专项历史继续存在。
21. **权限矩阵**：新增目标 `route:transfer`、`route:salary:adjust`；沿用 route:void/reactivate、salary:view/mine、费用归属等权限。转派中的工资核定归 transfer 权限；非转派调整使用独立权限。ADMIN 不作为代码特权；经营金额不能由 route:list 自动获得。
