## 磅单、附件和卸货事务

新增附件用途 `ROUTE_UNLOAD_WEIGHT_TICKET`，与 `WEIGHT_ADJUST` 独立。上传采用现有正式 Attachment API；仅允许持有 `route:unload` 的当前司机，且线路和当前参与人均处于 `IN_TRANSIT`，上传照片绑定具体线路。上传成功的文件先处于未消费状态；删除未提交图片仅从小程序待提交列表移除，已上传附件仍有审计与存储事实，不会被误称为正式卸货证据。

V10 `route_unload_evidence` 保存线路、最终参与人、原始重量版本、附件、上传人和绑定时间，以附件唯一约束阻止跨业务重复消费。卸货锁定线路与当前参与人，校验毛重、皮重和净重、1～10 张不重复的图片、用途、线路、上传人及未消费状态，再在同一事务内创建原始重量版本、绑定证据、完成参与人和线路，并写 Audit。任一步失败回滚正式卸货事实，已上传但未提交的附件仍保留为未消费状态，便于司机重试。完成后司机不能修改重量或磅单；授权纠错会创建新的重量版本及 `WEIGHT_ADJUST` 证据，不覆盖原始磅单。

卸货磅单的下载/列表按具体 Attachment 的目的和业务范围重新校验：管理人员需要 `route:list`；司机需要 `route:list` 且与线路存在正式参与关系；无关账号不能仅凭附件 ID 下载。额外检查发现旧 `WEIGHT_ADJUST` 纠错附件仅凭司机 `route:list` 即可按 ID 查看，已同步收紧为非 DRIVER 管理端权限，列表与下载均不向司机开放。转派后的旧参与人不能再上传正式磅单或卸货；仅最终 current 司机可提交。相同线路重复卸货由线路状态、原始版本唯一性和附件唯一性共同防重。Audit 只记录附件 ID、线路/参与人、重量和操作者，不复制文件二进制、临时 URL 或凭据。

## 达标、经营与司机脱敏

- 自有司机按当前参与人的公司车辆配置计算阈值，结果保持 `true`/`false`；未达标仍允许卸货完成。外协参与不查询公司车辆，也不为车牌创建公司 Vehicle；阈值和达标结果为 `null`，管理端显示“不适用”。旧历史不做无法可靠判定的批量改写。
- 本阶段检查的现有报表/看板/月结查询未发现达标率聚合分母；重量的 nullable 达标事实可被读取，后续若新增达标率，分母必须仅含非 null 记录。
- 司机线路列表、详情、发车和卸货返回统一使用专用 `DriverRouteResponse`。DTO 不包含含税单价、工资、收入、总支出、利润、达标结果或阈值；管理端正式 Route DTO 仍按权限提供完整事实。重量版本历史原先仅以 `route:list` 授权，会向司机暴露阈值且允许猜测其他线路 ID；已补非 DRIVER 校验，司机调用一律 403，小程序线路详情与卸货页也不显示这些敏感字段。
- 当前执行车牌由 current Participant 决定：自有司机关联公司车牌，外协司机使用参与人外协车牌。历史参与车辆仅在管理端历史视图中呈现。`salary:mine` 独立接口未被线路 DTO 改动；外协司机不进入自有工资单体系。

## 双端交互

小程序卸货页保留冻结的 Design System：毛重、皮重、自动净重、独立拍照/相册上传区、图片缩略图与数量、误传移除、确认摘要和底部提交。无图阻止确认；上传失败提示重选，成功的图片不清空；卸货请求结果未知时保留表单和图片，要求先刷新线路状态，避免重复点击。完成线路详情提供“查看原始卸货磅单”入口，进入现有卸货页只读预览，不显示再次提交或移除入口。转派历史司机的详情将“下一步”提示改为“等待接手司机发车”，不误导旧司机操作；后端 current participant 权限边界未变。未加入磅单 OCR。

管理端线路详情的重量区增加“司机卸货原始磅单”只读列表/预览与上传人、时间，明确区别后续重量纠错附件；卸货动作由司机完成，管理端没有伪造司机磅单的快捷操作。最终经营档案视觉整理留 UI-FIX。
