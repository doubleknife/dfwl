# R7-V3-C 工资出勤与调度月度台账实施及唯一性复审报告

## 范围与结论

以提交 `6bfb333490fef7990b3d7914e64610f1387c4335` 为开发起点，业务规则仅采用 `AGENTS.md` 与 `docs/01～07 V3.0`。本阶段实现管理端工资台账、司机月度汇总与转派全员核薪、自有司机出勤，以及自有和外协车辆月度调度台账。没有实施 V3-D～G 模块，没有提交代码。真实 GUI 人工验收统一记为 **DEFERRED TO V3-R**，不记 PASS。

## 实际实现

| 业务能力 | 当前实现与唯一口径 |
| --- | --- |
| 工资台账 | `/driver-salaries` 按月份、司机、司机类型、线路模板、运输任务及普通/转派任务服务端筛选与分页。汇总和司机维度汇总使用相同筛选条件；转派由正式 `source_type=TRANSFER` 参与链判定。工资总额、自有/外协金额、参与次数和转派任务数均由 `transport_participant.salary_amount` 派生。 |
| 转派工资核对 | 工资详情按顺序展示全部 Participant、当时车牌/车挂、发车/结束事实和当前工资；`salary:adjust` 用户一次提交全员核薪。复用 `TransportTaskService.confirmParticipantSalaries` 的全员集合校验、版本比较、幂等、非负金额、同额不写历史及原因/操作人/时间历史。工资允许 0.00；参与人不删除或重建。 |
| 工资 Excel | `/driver-salaries/export` 读取完整服务端筛选范围，不使用前端当前页；列标题及司机类型/转派/状态采用中文业务名称。单独校验 `salary:export`。 |
| 自有司机出勤 | `/attendance` 只纳入 INTERNAL，读取 Participant `departed_at` 的本地自然日；同日多次发车仍为 1 天，跨日卸货不另计。月表按司机×1～31 日展示，可点日期看真实发车任务；Excel 使用同口径。 |
| 车辆调度月账 | `/dispatch-ledger/internal` 按公司车辆、执行司机和当时车挂快照分别成行；`/dispatch-ledger/outsourced` 按本次外协车牌与执行司机成行。每天计 Participant 的实际发车次数；同车不同司机不合并成单一“当前司机”，转派后二次真实发车分别计入各车。两类完整 Excel 使用同口径。 |
| 权限与契约 | 新增 `salary:export`、`attendance:view/export`、`dispatch:ledger:view/export` 原子权限，并同步单一数据库 baseline、H2 测试 schema、OpenAPI 和管理端导航。工资/出勤筛选选项由本业务域提供可搜索只读 API，角色无需同时拥有 `driver:list`、`template:view` 或 `task:view` 才能使用页面；导出独立控制，后端逐接口校验且显式拒绝 DRIVER。 |

工资月份按 TransportTask 业务日期归档；出勤和调度月份只按 Participant 实际发车的服务端本地日期归档。两种日期不互相替代。

## 旧实现清理与边界

- 工资唯一可写权威仍是 Participant；`participant_salary_history` 为只读调整历史。未建立工资统计表、出勤表或调度统计表，未恢复 task 级工资字段或旧 `driver_salary_entry`。
- 退役未被路由引用的旧工资管理组件和旧参与人工资页，移除不再可达的旧 `/reports/attendance` 前端调用及旧 `DriverSalaryService` 管理端列表方法。小程序自有司机工资单仍从同一 Participant 金额读取；外协工资单继续拒绝。
- `departure_event` 是发车事件记录；本阶段月账以 Participant `departed_at` 和冻结车牌/车挂事实生成，不读取当前绑定推写历史。经营/月结对工资事实的统一读取由 V3-E 验收，不在 V3-C 偷做报表重构。
- 单一初始化数据库仅在权限种子上同步改动，Flyway 仍只有 `V1__baseline_schema.sql`；本阶段没有兼容 Migration、双写或旧 API。
