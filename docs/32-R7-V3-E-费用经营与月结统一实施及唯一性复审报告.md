## 实现与唯一财务事实

| 能力 | 当前正式实现 |
| --- | --- |
| 费用台账 | 批准后的 `ExpenseEntry` 为普通费用唯一事实；服务端筛选、分页、汇总、详情、来源/审批批次/归属历史/Audit 与完整筛选结果 Excel 导出。`applicationScope` 永不因后续归属改变。 |
| 归属 | DAILY 可以从未归属绑定任务，或调整已归属任务；TASK 初始直接归属。服务端按目标任务全部正式 INTERNAL Participant 的当时公司车辆事实匹配，非参与车辆硬拒绝。每次变更做版本校验、历史与 Audit。 |
| 冲销 | 原费用不改写，新增关联负金额 `ExpenseEntry`；同一原费用再次冲销被拒绝。冲销随原费用当前归属参与任务净额，公司费用净额亦相应变化。 |
| 经营公式 | `FinanceFactsService` 是任务、列表摘要、模板聚合、公司汇总、看板与月结的统一计算来源。已完成任务收入＝当前有效净重×任务实际含税单价；支出＝任务实际信息费＋非取消 Participant 核定工资＋当前归属的有效费用净额。信息费不是 ExpenseEntry。 |
| 公司经营 | 公司汇总包含本月所有有效 ExpenseEntry，含未归属 DAILY；绑定任务不改变公司费用总额。收入按完成月份，信息费/工资按任务业务月份，正式费用按费用业务月份取数；页面明确说明此口径。 |
| 月结 | 同一月份可生成 V1/V2…不可变快照；新版本读取当前有效事实，前版快照不回写。详情展示业务编号、金额；差异展示变化类型、前后业务金额、原因、操作人/时间及可用审批信息；无事实变化的新版本差异为零。 |
| 页面 | 管理端新增费用台账/归属、任务经营、模板经营、公司经营、首页看板与月结版本页面；运输任务列表批量读取同一经营摘要，已完成任务详情显示同一 API 的归属费用明细。无数据库 ID 输入或裸 JSON 财务页面。 |

数据库仅维护单一 Flyway `V1__baseline_schema.sql`，同步 `database/database.sql` 与 H2 测试 schema；本阶段仅为 `expense_entry` 增补正式票据/发票/备注/站点与并发版本字段及原子权限。OpenAPI 仅列当前可达的 V3-E 契约。未引入开发旧版本迁移或兼容写 API。

## 旧实现清理与四项唯一性复审

| 检查 | 结果 |
| --- | --- |
| 需求唯一 | 仅以正式 V3.0 的费用、经营与月结规则实现；未用历史 docs 覆盖。PASS。 |
| 业务唯一 | 费用由 V3-D 审批通过落 ExpenseEntry；后续归属/冲销由费用台账服务执行。旧直接新增费用、旧报表与旧月结不在正式运行路径；抽查旧 `/expenses`、`/reports/dashboard`、旧 `details-page` 均为 404。PASS。 |
| 数据唯一 | `ExpenseEntry` 是费用事实，`TransportParticipant.salary_amount` 是工资事实，`TransportTask.actual_information_fee` 是信息费事实，`WeightVersion` 是有效重量事实，`Settlement` 快照是历史版本事实；没有第二套可写财务汇总表。PASS。 |
| 代码唯一 | 删除旧 Expense 直写 Controller/Service/Handler、旧 Report 与 Settlement Controller/Service/Repository 以及其专用 DTO；管理端删除旧费用、报表、月结、看板页面与 API 调用。保留审批资源校验所需的只读 `ExpenseApplicationPolicy` 和仅含车辆/司机/任务存在性读取的 `ExpenseRepository`，它们不能写费用。所有正式经营计算统一到 `FinanceFactsService`。PASS。 |

`ExpenseApplicationPolicy` 与 `ExpenseRepository` 的处置为 **KEEP / READ-ONLY VALIDATION**。复查确认：Policy 只校验费用类型、提交权限/司机身份、车辆、司机和任务资格；Repository 仅有三个 `SELECT COUNT(*)` 存在性查询。两者不写 ExpenseEntry、不修改费用金额或当前任务归属、不维护第二套费用状态；旧 `/api/v1/expenses` 不可达，不能绕过正式 `Expense Application → Approval → ExpenseEntry` 链路。V3-D 费用申请、外协拒绝与司机/车辆/任务候选校验测试，以及本阶段财务权限负向测试继续保留。

反向引用复查：旧费用 Controller/Service/Handler、旧报表/结算计算类及旧管理端页面在当前主代码与管理端入口无引用；`ExpenseType` 仍由正式审批类型校验复用；只读费用资源校验由现有审批服务引用，故保留其校验能力。没有为了清理旧代码削弱司机、车辆或任务的资源检查。
