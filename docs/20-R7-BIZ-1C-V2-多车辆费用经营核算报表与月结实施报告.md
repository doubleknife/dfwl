## 费用事实与车辆资格

`expense_entry`（含冲销记录）仍是唯一金额事实；审批通过和导入只产生该事实，不另建成本表。`expense_attribution_history` 保存归属变更，不被当作新的金额。审批来源、导入来源与人工来源在当前有效费用的公司口径中只计一次。

线路合格费用车辆来自同一路线所有有效 **INTERNAL** 参与人的 `company_vehicle_id` 去重集合；保留 `TRANSFERRED`、已指派但等待接手、工资为 0 的参与人。普通 `CANCELLED`、`LEGACY_ENDED` 以及所有 `OUTSOURCED` 参与人不取得公司车辆资格。外协车牌字符串与公司车牌相同也不授予资格。`GET /api/v1/expenses/eligible-route-vehicles` 为受现有费用权限约束的窄候选查询，人工录入、重新归属、审批最终落账及导入正式提交均在后端重新核对。

能源费用匹配使用公司车辆与整条线路的**首次真实发车至最终卸货**窗口，两个端点包含在内；时间按数据库时间戳精度比较，不按转派节点切段。唯一匹配才自动归属。零匹配或多匹配均保持 `PENDING_ATTRIBUTION`，不猜线路；人工选择仍须通过目标线路和车辆资格。已有费用导入处理器仅按现有标准化费用事实接入这套判定，没有新增未提供的供应商文件列或去重规则。

## 未归属、重新归属与事务

有效未归属费用不进入具体线路支出，却进入公司总支出。能源费用自动判定为待归属后，即使请求的预期归属类型是 `DAILY`，也以待归属公司成本呈现；当前归属事实与状态由正式 API 可查询。

`PUT /expenses/{id}/attribution` 支持 R1→R2、R1→未归属、未归属→R2；原因必填，保存旧/新归属、操作者、时间到专项历史，并写 `ATTRIBUTION_ADJUST` Audit。相同目标重试不重复写历史。费用行和目标线路在事务中加锁；归属与冲销、删除、作废等交叉操作均重新核对当前状态和车辆资格，失败回滚。归属变化只移动线路成本，不改变公司费用净额；冲销由原记录与反向记录净额计算。

## 线路经营与公司经营

| 口径 | 当前实现 |
| --- | --- |
| 线路收入 | 已完成且当前有效线路的最终有效重量 × 含税单价，使用数据库 DECIMAL。 |
| 线路费用 | 当前有效归属于该线路的费用净额；未归属不计。 |
| 参与工资 | 该线路有效参与人各自核定工资之和，包含外协参与工资和 0 工资参与；不再只取 `route_task.driver_salary`。 |
| 线路总支出/利润 | 线路费用 + 参与工资；利润为收入减总支出。 |
| 公司收入 | 所有当前有效线路收入。 |
| 公司支出/利润 | 已归属费用、有效未归属公司费用、日常费用及有效参与工资均计入，`expense_entry` 每笔只计一次；利润为收入减总支出。 |

只有 `COMPLETED` 线路可作废。后端要求原因和 `acknowledgeBusinessImpact=true`，管理端弹窗明确收入、工资、归属费用和利润退出当前有效线路经营。作废/恢复仅改变当前经营查询的生效分类，保留原线路、参与、费用与审批事实，不擅自改写费用归属：作废线路的公司真实费用仍计入公司总支出。恢复完成状态后线路经营重新纳入。作废/恢复 Audit 记录操作人、原因以及前后经营摘要。

## 查询、报表与权限

- `GET /reports/completed-routes` 服务端分页，支持 `COMPLETED`/`VOIDED` 区分，返回净重、达标兼容字段、收入、费用、参与工资、总支出、利润与参与摘要；`GET /reports/completed-routes/{id}` 返回单线路经营档案、参与工资和历史引用、按类型/车辆/来源费用汇总、正式费用明细分页、来源及归属历史。没有由前端逐行 N+1 聚合。
- `GET /expenses` 增加 `routeId` 等组合筛选和准确 `total`，按**当前归属**查找；管理端用可搜索线路选择器，归属变化后刷新反映，不要求业务人员手填数据库 ID。
- 看板/利润、车辆支出、司机支出、能源费用、出勤及趋势报表改为参与工资与费用事实口径。车辆资产类报表不把外协文本车牌当公司车辆；运输维度可显示外协车牌但保留来源区分。已作废线路退出当前有效线路经营，其费用仍保留公司真实成本。
- 经营金额继续要求 `report:profit`；`route:list` 单独不足以查看收入、工资或利润。费用调整、月结版本/差异、工资明细沿用各自现有权限，没有新增宽泛权限码。

## Settlement V2 与差异

V9 为 `settlement_version` 增加 `unassigned_expense DECIMAL(18,2)`，旧行默认 0；**未更新或覆盖旧版本的 detail/snapshot/diff**。新版本冻结线路经营、参与人顺序/类型/公司车辆或外协车牌/有效工资、重量、费用净额与必要来源、未归属公司费用、公司合计和作废/恢复状态。审批来源费用仅保存申请日期、费用类型与金额、发起人、最终通过人、通过时间等摘要；不复制附件或过量审批 JSON。

新版本的差异包含 `SALARY_ADJUST`、`WEIGHT_ADJUST`、`EXPENSE_ATTRIBUTION_ADJUST`、`ROUTE_VOID`、`ROUTE_REACTIVATE`、冲销 `REVERSAL` 及转派等业务类型。纯转派不被误判成调薪；能从历史可靠定位的操作人、时间、原因和收入/支出/利润影响随差异返回，无法可靠追溯的字段不猜填。`details-page`、`diff-page` 服务端分页并返回 `businessSummary`/前后摘要，Raw JSON 只保留技术用途。月结生成以数据库 `REPEATABLE_READ` 事务获取一致快照，对版本竞争作有界重试；旧版不变性由测试验证。

真实浏览器查看 V7 时发现：前后快照的**业务结构相同**，但 JSON 对象字段顺序变化被原字符串比较误判成差异，产生 5 条零金额的假 `MODIFY`/归属/冲销。已改为解析后的 JSON 结构比较，并新增“事实不变则新版本差异为空”测试。管理端把本阶段新增差异码转成中文，费用业务摘要把类型和归属类别转成中文；高级信息仍允许查看原始 JSON。

## 剩余项与阶段结论

- **BLOCKER：无。** 月结 V8 空差异、费用筛选布局、多参与且有费用的线路经营档案均已完成真实浏览器人工核对并通过；经营金额与正式 API 一致。
- **DECISION REQUIRED：无。** ExpenseEntry 可安全表达冻结规则，未建立第二套费用金额事实。
- **NON-BLOCKING 继承：** BIZ-1A 的 Settlement 迁移前后逐字段/hash 不变性总验收仍在 BIZ-1R；正式 Word 缺少 `soffice.exe` 逐页视觉核验。旧月结版本在本阶段的业务测试中保持不变。
- **专用测试库历史说明：** 修复前生成的 V7 含 5 条 JSON 字段顺序造成的零金额假差异。月结历史不可变，因此没有篡改 V7；在同一事实下生成的 V8 已无该假差异。这是本阶段测试库旧版本的可追溯记录，不是当前新版本算法仍存在的缺陷。
- **阶段结论：** R7-BIZ-1C V2 实施与关闭前验收均通过，可以正式关闭。当前不提交代码，不进入 BIZ-1D/UI-FIX/R8-2。
