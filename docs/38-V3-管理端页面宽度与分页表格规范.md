# V3 管理端页面宽度与分页表格规范

管理端页面主体使用完整可用内容宽度。列表、数据表和双栏工作区不设置统一像素上限；费用申请等长表单使用 `ui-form-page`，保留 1120px 的阅读宽度。详情抽屉按自身内容滚动，不随列表表格高度变化。1366×768 与 1920×1080 下，页面主体不得出现横向滚动。

正式服务端分页列表使用 `DataTable` 的 `ui-paged-table` 类和公共 `PaginationBar`。表格容器按自身在视口中的起点计算剩余高度；表头粘在容器顶部，表格只在容器内横向及纵向滚动。分页栏紧随表格并在工作区滚动时保持底部可见。加载、空数据与错误后的表格区域不得被数据行数撑高。

每页条数为 10、20、50、100，初始值 20。切换条数时保留现有筛选状态、从第 1 页向服务端重新请求并重置表格滚动；切换页码也重置表格滚动。总数和总页数使用服务端响应，禁止对已获取的单页结果二次截取并当作服务端分页。权限目录是一次性完整读取的只读目录，取消伪分页，在独立滚动容器内展示。

月度出勤网格、导入预览及导入明细、调度草稿、审批节点编辑、详情抽屉表格与经营统计图表使用各自的业务容器。导入预览和详情中的本地行切换暂保留原 50 行规则，不显示服务端列表的条数选择器。实体选择器保持原有 100 条查询与独立分页，不套用正式列表高度。

人工验收检查两种目标分辨率下的页面宽度、表头与数据对齐、表格滚动、分页栏可见性、条数切换后的筛选与页码，以及复杂页面例外布局。本轮代码级校验不替代人工 GUI 验收。
