# R7-V3-D 审批与费用申请实施及唯一性复审报告

## 范围与结论

以 `0d4b2f937fbf055ceea08c00ac1097c7feb58311` 为开发基线，业务规则仅采用 `AGENTS.md` 与 `docs/01～07 V3.0`。本阶段建立唯一可达的 V3 审批流程、DAILY/TASK 费用申请、固定 DAILY Excel 一批一审，以及批准后一次性落账。未实施 V3-E 的费用归属工作台、完整费用台账、经营和月结，也未实施 V3-F 轮胎最终页面。真实 GUI 人工验收为 **DEFERRED TO V3-R**，不记为 PASS。本阶段未提交代码。

## 实施与旧入口清理

| 能力 | 实现与唯一口径 |
| --- | --- |
| 模板与流程 | 模板稳定业务类型仅为 `EXPENSE / GENERAL / TIRE_REPLACEMENT`；流程发布后冻结 FlowVersion 与稳定 `flowNodeId`。新版本不改变在途实例。发起人角色及审批人由服务端校验。 |
| 指定步骤打回 | `/approvals/{id}/returnable-steps` 仅返回当前实例冻结流程的合法目标；前端展示步骤业务名并提交 `targetFlowNodeId`，服务端再次校验。无中间候选时不显示入口。打回到申请人后的重新提交生成新 Submission Version；Action 与 Audit 留存。旧 `targetNodeOrder` 不在正式 API、OpenAPI 或当前双端入口中。 |
| DAILY/TASK 费用 | 首步明确选择不可变 `applicationScope`。DAILY 可单笔或唯一固定 Excel；司机和公司车辆分别验证存在，不要求当前绑定。TASK 仅单笔，按司机正式参与的 TransportTask 候选选择，服务端复核；外协司机由后端拒绝。金额必填且大于 0，其他固定字段按 V3.0 处理。 |
| DAILY Excel | 系统下载固定模板；上传、Preview、行级中文错误与合计、Confirm。任一错误阻止整个申请；N 行形成一个 ApprovalInstance 与 N 条申请明细，不是一行一个审批。 |
| 正式费用事实 | EXPENSE 最终批准按 `approval_instance_id + approval_item_no` 唯一关系写 ExpenseEntry；重复请求键、重复批准和并发重试不能重复落账。TASK 批准后已带目标任务；DAILY 可暂不归任务。`applicationScope` 与后续经营归属分开保存。 |
| 非费用业务 | GENERAL 批准不写 ExpenseEntry。TIRE_REPLACEMENT 由独立轮胎 Handler 生效：库存轮胎从可用变为已申领并写轮胎历史，不写普通费用；轮胎最终管理界面仍属 V3-F。 |
| 双端 | 管理端审批中心按待我处理、我的申请、审批记录、流程与模板配置组织，费用申请按选择范围、填写/上传、核对、提交组织；小程序增加审批中心/详情和费用申请，外协费用入口及后端权限均禁止。使用业务 Label、表格、时间线、附件预览和 Loading/Empty/Error 状态。 |

原审批模板、审批实例、直接新增普通 Expense 及旧动态费用 Excel 的 Controller 已退出正式路由；当前正式可写入口只有 V3 Controller。旧源码中的 `targetNodeOrder` 引用仍处于不暴露的退役类中，不是当前 API/服务端调用路径；其反向引用只在该退役包内，未进入 OpenAPI、管理端、小程序或当前启用测试。后续重建轮胎最终业务时可清理相应退役源码，不恢复第二套入口。附件访问查询已适配 V3 `instance_id/submission_version_id` 关系，审批附件 Purpose 与预览读取在正式 API 验证通过。

## V3-D 局部四项唯一性复审

| 项目 | 结论与反向引用 |
| --- | --- |
| 需求唯一 | **PASS**。审批类型、FlowVersion、打回与费用申请只依据 01～07 V3.0；旧 docs 不参与规则决定。 |
| 业务唯一 | **PASS（当前正式可达范围）**。V3 Controller 是唯一审批/费用写入口；EXPENSE、GENERAL、TIRE_REPLACEMENT 后果由业务类型分派。旧直接费用与动态导入 Controller 不可达。 |
| 数据唯一 | **PASS**。ApprovalInstance/Submission/Action 保存审批事实；ExpenseEntry 仅保存批准后的费用事实；`applicationScope` 不被任务归属覆盖，批准落账有稳定唯一键。 |
| 代码唯一 | **PASS（当前正式可达范围）**。双端只调用 V3 API；没有旧 `targetNodeOrder` 与 `targetFlowNodeId` 同时对外，也没有直接新增普通 Expense 与审批落账并行。退役包中的旧服务/DTO 仍有源码反向引用但无正式 Controller、菜单或 OpenAPI 入口，未构成第二套可写运行路径。 |

对 V3-0 清理地图中的审批模板/流程、节点目标、费用申请与旧动态 Excel **REBUILD/MERGE/DELETE** 项完成正式路由、前端调用、OpenAPI 和当前测试反向扫描；旧退役源码不作为业务事实来源。V3-E 的后续 DAILY 人工归任务与完整费用经营、V3-F 的轮胎最终页面均未误报为本阶段完成。
