## 2. 最终实现与零元订单

| 能力 | 实际实现 |
| --- | --- |
| 模板配置 | 一公司一份当前生效映射；新增需样本，重新上传样本必清空四项选择，不传新样本可在已存表头上调整。四列按列位置选择，允许同名表头，不建立版本体系。 |
| 文件预览 | 前端用同一通用解析器读取 `.xls/.xlsx` 第一个工作表，自动建议并可修正表头行；空行后继续扫描；合计行不计订单；异常显示原始行号。预览只读、异常阻止确认。取消不上传原文件。 |
| 正式确认 | 后端重新打开上传的原始 Excel，核对四项映射、所有候选行、订单身份、时间、车牌、金额、数量与总额；权限、车辆、来源和金额精度在服务端验证。原文件、哈希、映射快照、批次、来源订单和入账结果留痕。 |
| 正常订单 | 唯一键为 `来源系统 + 订单编号类型 + 原始订单号`；同来源重复、文件内重复和并发重复不再生成第二条来源订单或费用，重复金额变化拒绝。不同来源相同订单号可分别入账。 |
| 零元订单 | 金额 `0.00` 是合法订单：保存 SourceOrder、批次、原文件和行号，参与正式去重，结果单列“零元不入账”；**不生成 ExpenseEntry，不计费用、经营或月结**。金额缺失、负数、无法解析和超精度仍阻止错误批次提交；普通费用的正金额业务校验未放宽。 |
| 自动归属 | 仅按公司车辆、真实充电时间、Participant 当时车辆快照和实际发车/结束区间寻找任务。唯一匹配时写同一 ExpenseEntry 的当前任务归属及归属历史；无匹配或多匹配仍正式入账但保持未归属。 |
| 追溯与权限 | ExpenseEntry → SourceOrder → ImportBatch → OriginalFile；费用详情可查原始订单，具备 `charging:view` 时可下载原文件。原文件接口独立鉴权并拒绝司机，未通过可猜测存储键开放下载。 |
| 对账 | 每批 `有效订单数 = 正常入账订单 + 零元订单 + 已存在重复订单`，异常订单另列且不能提交；导入历史服务端分页，显示数量与金额。 |

后端只使用一个通用四列核验服务，没有为 12 家公司建立 Java 专属解析器。`applicationScope=DAILY` 表示费用来源，`currentTaskId` 是可调整的当前经营归属，两者未合并为一个字段。充电直接入账属于本阶段独立且经授权的来源类型，仍写唯一 ExpenseEntry，不开第二套费用账或财务计算。

## 3. 12 家真实样本与完整性

只读扫描业务方提供目录，实际为 **12 份文件：11 份 `.xlsx`、1 份晋宁人滴 `.xls`**。全部由前端通用解析器读取；同一批预览数据和原文件再由后端通用核验服务逐份确认，无公司专用 Java 解析。按真实表头选择四列，未猜测金额列。

| 样本核验 | 结果 |
| --- | --- |
| 有效订单候选 | **2,003 条**，其中正金额 **1,911 条**、零元 **92 条**。 |
| 正金额合计 | **¥301,738.56**；零元不进入该金额。 |
| 异常行 | **0 条**；4 个汇总/空身份尾行明确排除，保留行号；保山金粒的 Excel 公式合计行按缓存金额与前序订单总额核对。 |
| 空行和精度 | 空行后的订单继续保留；长数字订单号作为文本保持原样，越过 Excel 数字安全精度时明确报错；金额用分/DECIMAL 对账。 |
| 客户端遗漏防护 | 有金额而缺少订单身份的中间行会报错，不能静默跳过；真实汇总尾行需满足前序订单合计才忽略。后端同样检查原始工作表中未纳入预览的候选行。 |

上述 12 家样本验证仅证明本批实际文件的通用解析与核验；将来公司改变结构时仍须更新映射并重新预览，不能假定任意新格式自动适配。

## 5. 四项唯一性复审

- **需求唯一 PASS**：正式规范仍为 `AGENTS.md + docs/01～07 V3.0`，并将本阶段确定的充电专项与零元订单规则直接同步到正式章节。历史报告不作为新规范。
- **业务唯一 PASS**：充电订单只有“当前映射 → 只读预览 → 人工确认 → 服务端核验 → 统一入账”正式链。DAILY 混合审批、TASK 单笔及通用导入中心未改动；取消预览不落账。
- **数据唯一 PASS**：SourceOrder 是第三方订单身份和零元追溯事实，ImportBatch/OriginalFile 是来源证据，ExpenseEntry 是唯一正式费用事实；任务归属复用现有归属历史。无第二套费用表、影子金额或零元 ExpenseEntry。
- **代码唯一 PASS**：一套前端四字段解析器和一套服务端通用核验/写入服务；没有 12 套 Java 解析器、旧动态费用导入写入口或与 ExpenseEntry 并行的财务写路径。公司经营仍由 V3-E 统一财务服务计算。
