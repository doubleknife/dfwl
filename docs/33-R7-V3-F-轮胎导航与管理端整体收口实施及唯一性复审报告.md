## 2. 轮胎正式链路

| 能力 | 最终实现 |
| --- | --- |
| 入库 | `/tire-imports/template` 下载唯一四列表头“到货时间、物料描述、条码、胎号”；真实 XLSX 上传后 Preview、行级校验、Confirm、结果和历史。非标准表头、文件内及库存重复胎号/条码均拒绝或记录中文行错误。新胎状态 `AVAILABLE/可用`。 |
| 库存与维护 | Web 只提供库存查询、详情、入库和授权维护；维护字段限胎号、条码、物料描述、到货时间。版本冲突、已申领状态、胎号/条码唯一性均由服务端校验；变更记录 before/after、原因、操作人、时间，同时写 TireHistory 和 Audit。 |
| 换胎申请 | 仅小程序自有司机持 `tire:request:create` 且有当前公司车辆时进入；照片作为 `TIRE_OCR` 附件上传，OCR 原始记录保留，司机确认胎号后匹配可用轮胎，再选 `TIRE_REPLACEMENT` 模板提交。外协司机及 Web 账号由后端拒绝。 |
| 审批生效 | 复用 V3-D ApprovalInstance/FlowVersion；待审批不改变轮胎正式状态，但防止重复申领。打回不消耗库存；通过时在事务内改为 `CLAIMED/已申领`，写 TireHistory/Audit，不生成普通 ExpenseEntry。 |

并发复审发现并修复一个 V3-F 范围内的重复申领风险：MySQL `REPEATABLE READ` 下，事务先读取 OCR/幂等事实建立快照、再等待轮胎行锁时，普通 `COUNT` 可能看不到刚提交的待审申请。现于锁住轮胎行后对 `(tire_id,status)` 索引做 `FOR UPDATE` 当前读；没有新增第二套状态或写入口。受影响后端全量测试、标准 package、全新 V1 baseline 与真实 MySQL 快照/当前读对照均重新通过。

本机隔离 API 环境使用 `OCR_DISABLED` 提供方：真实照片上传及 OCR 记录、人工确认、库存匹配和审批闭环已验证；**外部 OCR 自动识别准确率/可用性未在本环境验证**。小程序已区分“识别暂不可用”与“未识别出胎号”，允许司机对照原图手动核对，不把失败记录冒充识别成功。

## 3. 导航与正式页面收口

管理端导航落为八个一级业务域：工作台、运输调度、费用管理、工资管理、审批中心、车辆与基础资料、经营分析、系统管理。二级叶子按 `/me.permissions` 过滤；无可访问叶子的父级隐藏。调度中心有三级分组；叶子高亮、父级展开、Breadcrumb 与 PageHeader、刷新及浏览器后退由同一路由状态维护。

当前挂载页面包括：经营看板；调度工作台、运输任务、线路模板、任务导入、两类调度月台账；费用申请/台账/归属；工资台账/转派核对/出勤；审批待办/我的申请/记录/流程配置；司机/车辆/车挂/绑定/货物/轮胎库存/入库；任务与模板经营、公司经营、车辆/司机支出、能源费用、月结；用户/角色权限/操作日志/导入历史。指定充电公司专项导入属于 V3-G，本轮未伪造入口。

已从正式路由及文件中删除旧审批页、审批向导、旧系统页、旧通用导入页、旧轮胎页及重复审批模型。MasterData、System、Salary、Approval、TransportTask、Expense 等保留的组合组件改由明确叶子路由选择对应业务区域，不再把旧大 Tab 暴露为一级导航。轮胎 Web 页面没有“发起换胎”按钮；旧隐藏 URL 不映射可写页面。根 README 与小程序 README 的旧阶段说明也已更新。

静态检查当前可达 Vue 页面：无 `<pre>` 裸 JSON、高级 JSON 调试块、数据库 ID 输入或直接显示 `IN_STOCK/CLAIMED/AVAILABLE` 技术枚举；业务选择使用已有 EntityPicker/业务选择器。保留了已确认的 TransportTask 重量记录、原始磅单与纠错证据分区及局部纠错操作。宽表横向滚动限制在表格容器；响应式 CSS 和导航折叠支持 1366×768、1920×1080 的结构要求。**像素级及真实浏览器人工观感仍待 V3-R。**

## 6. 四项唯一性复审

- **需求唯一 PASS**：轮胎四字段、Web/小程序职责及导航目标以 `AGENTS.md + docs/01～07 V3.0` 为准；历史 docs/27 只用于反向定位。未引入费用专项模板或 V3-G 规则。
- **业务唯一 PASS**：入库仅固定模板；Web 仅库存/维护；换胎申请仅小程序司机链；审批通过统一由正式 TireApprovalEffect 生效，没有直接 Web 换胎或普通费用旁路。
- **数据唯一 PASS**：Tire 是库存状态权威，TireRequest/OcrRecord/Attachment 分别保存申请、识别与原图，ApprovalInstance 保存审批，TireHistory/Audit 只记变更。未复制任务、工资、费用或月结事实。
- **代码唯一 PASS（当前可达路径）**：旧轮胎 Controller/Policy/Handler 和旧页面删除；导航只挂载正式页面；单一 V1 baseline、测试 schema、OpenAPI 与当前 API 同步。仓库中个别未挂载的历史审批服务类仍为编译态旧代码，但没有 Controller/路由可达写入口；若后续清理，应另行做反向引用与测试确认，不能把它记为当前可写双轨。
