# 车队经营管理系统架构与部署说明 V3.0

本文件说明首次正式上线的系统组成、部署和运行维护。业务规则以 `AGENTS.md` 与 `docs/01～07` 为准，数据库结构以 `docs/03` 和 `database/database.sql` 为准，接口以 `docs/04` 和 `docs/openapi.yaml` 为准。本文件不建立第二套业务契约。

## 1 系统架构

系统由 `admin-web/` 的 Vue 3 + Vite 管理端、`mini-program/` 的微信小程序、`backend/` 的 Java 21 + Spring Boot 服务、MySQL 及受控附件目录组成。Web 和小程序均调用 `/api/v1`；服务端统一负责身份、角色、页面与按钮权限、业务状态、事务、审计和文件访问。管理端页面路由在 `admin-web/src/router/routes.js`，小程序页面注册在 `mini-program/app.json`；后端功能注册表在 `backend/src/main/java/com/dfwl/fleet/security/FunctionRegistry.java`。前端可见性不代替服务端校验。

后端使用 Spring JDBC、Spring Security、Flyway 和 MySQL Connector/J。数据、审批、工资、费用、运输及结算正式事实写入 MySQL；附件原文件存于 `fleet.storage.local-root`，数据库保存附件元数据与业务关联。腾讯云 OCR 仅用于有资格的轮胎图片识别；OCR 候选不代替用户确认和库存校验。系统未使用 Redis，也不依赖定时任务生成正式费用、工资或结算事实；这些事实由正式业务动作写入。

## 2 运行环境与构建

后端使用 Java 21、Maven 和 MySQL 8；管理端使用 Node.js、Vite 构建。微信小程序在微信开发者工具中导入 `mini-program/`，按目标环境配置合法请求、上传和下载域名及正式 AppID。版本以 `backend/pom.xml`、`admin-web/package.json` 和平台项目配置为准，不将某台开发机的安装路径写成系统要求。

在 `backend/` 执行 `mvn package` 产生可运行 JAR；在 `admin-web/` 执行 `npm ci`、`npm run test`、`npm run build`，将 `dist/` 部署到静态站点。Web 的 `VITE_API_BASE_URL` 指向该环境的 API，代理或服务器应将 `/api/v1` 正确转发给后端。小程序的 API 地址按 `mini-program/app.js` 当前配置和微信平台合法域名设置，正式环境使用 HTTPS。后端默认监听 8080，健康检查使用 `/actuator/health`；端口由部署配置覆盖时以实际配置为准。

## 3 数据库初始化

首次上线使用单一最终 schema。`database/database.sql` 是可审阅的初始化契约，后端实际启动由 `backend/src/main/resources/db/migration/V1__baseline_schema.sql` 的 Flyway baseline 初始化。两者及测试 schema 必须保持一致；同一数据库只选一种初始化方式，不重复导入。数据库和账号应预先创建并授予所需权限，初始化前先确认目标库和备份，禁止在已有正式业务事实的库上重放初始化脚本。本项目首次上线不执行旧开发数据迁移或兼容链。

启动后核对 Flyway 执行结果、基础权限与角色目录、健康接口及关键只读 API。管理员初始化以当前 baseline 的种子与正式权限规则为准；首次登录立即更换初始口令，文档、日志和工单不记录实际口令。正式业务历史上线后按 `01～07` 保留，不通过重新初始化解决数据问题。

## 4 配置与环境变量

打包配置位于 `backend/src/main/resources/application.yml`，生产覆盖配置位于 `application-prod.yml`。本机和服务器私有值通过环境变量或 JAR 外配置提供，例如 `--spring.config.additional-location=file:./.runtime/application-local.yml`；部署示例见 `deploy/env/dfwl.env.example`。私有文件不放入 Maven resources，不进入 Git 或前端构建产物。

| 用途 | 配置入口 |
| --- | --- |
| MySQL | Spring Boot 环境变量 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD`；基础配置的密码占位符也接受 `FLEET_DB_PASSWORD`。Flyway 使用同一数据源 |
| 环境与端口 | `SPRING_PROFILES_ACTIVE`、`SERVER_PORT`；如需停用 Flyway，使用 `SPRING_FLYWAY_ENABLED` |
| 附件 | `FLEET_STORAGE_ROOT` 对应生产附件根目录 |
| OCR | `FLEET_OCR_PROVIDER`、`FLEET_OCR_TENCENT_SECRET_ID`、`FLEET_OCR_TENCENT_SECRET_KEY`、`FLEET_OCR_TENCENT_REGION` |
| 管理端 API | 构建时的 `VITE_API_BASE_URL`，不得包含服务端凭据 |

`prod` profile 对附件根目录和 OCR 配置有环境要求；准备生产配置时按实际服务启动结果核对，缺少必要凭据应在启动阶段失败。`deploy/env/dfwl.env.example` 中的 `FLEET_DB_URL`、`FLEET_DB_USERNAME` 和 `FLEET_SERVER_PORT` 只是旧示例名称，当前配置未读取它们；部署时使用上表的 Spring Boot 名称或 JAR 外配置文件。不要将数据库密码、Token、云密钥或私有附件地址写入跟踪文件、命令输出、截图、日志或审计。若凭据误入工作区，应在提交前排除并轮换已暴露凭据。

## 5 附件与 OCR

附件目录应为专用持久目录，由服务账号读写，备份时与 MySQL 中的附件元数据保持同一恢复点。上传、下载与预览继续受申请人、审批资格、合法历史查看范围和附件 Purpose 校验；申请图片关联实际 Submission Version，审批图片关联实际 Approval Action，不能因重新提交覆盖历史图片。目录不可作为 Web 静态公开路径。

真实腾讯云 OCR 由 `backend/src/main/java/com/dfwl/fleet/tire/ocr/` 的 Provider 实现调用。普通构建和自动测试不需要调用云服务；启用真实 OCR 时提供服务端凭据，并用已授权的真实轮胎照片验证上传、识别、候选确认和错误反馈。识别失败不伪造成功，也不得跳过正式申请和库存校验。

## 6 会话、权限与安全

登录按 WEB、MINI 终端分别签发会话；有效期和撤销规则见 `docs/01/04/06`。MySQL 的 `auth_session` 仅保存 Token 摘要及签发、终端、到期、撤销和认证版本事实，明文 Token 不落库。正常服务重启可恢复仍有效的会话；角色授权变更安全刷新权限，不要求有效用户无故重新登录；角色、用户、司机停用及密码变更按正式规则撤销会话。受保护 API 还须检查页面／按钮权限和对象范围。

部署时限制数据库和附件目录访问、启用 HTTPS、配置最小权限服务账号，控制跨域与文件上传大小，定期轮换凭据。错误响应、日志和 Audit 不输出密码、明文 Token、云密钥或非必要证件资料。

## 7 日志、备份与运行检查

后端日志通过 `requestId` 关联请求与错误，不以用户可见弹窗暴露内部栈。关键业务动作写 Audit；日志轮转、保留期和备份位置由部署环境配置。至少备份 MySQL、附件原文件和服务端私有配置，并定期演练同一恢复点的恢复。恢复后核对附件引用、审批版本、运输历史、工资和费用台账及月结不可变版本；不直接改写正式事实。

日常检查包含进程、`/actuator/health`、数据库连接、Flyway 版本、附件目录空间和权限、OCR Provider 状态、Web API 转发、小程序合法域名、错误率与日志轮转。生产部署或配置变更须记录版本、时间、操作人和回退包位置；不能把自动构建通过记作人工 GUI 验收。

## 8 常见故障定位

后端启动失败先检查目标数据库、私有配置、Flyway 初始化结果及附件目录权限；不要通过清空正式库排障。401/403 依次核对会话到期／撤销、角色授权、页面和按钮权限、本人及审批节点资格。上传失败核对目录空间、文件 Purpose、大小及访问权限；OCR 失败区分未配置、外部服务错误和无候选。Web 空白或请求失败核对构建产物、`VITE_API_BASE_URL` 与代理；小程序核对 AppID、HTTPS 和合法域名。业务写入失败使用 `requestId` 查服务端日志与 Audit，不直接修改数据库事实。
